更新日期：2026-09-08。

主要基础修复与漫画单图首版已完成，本地生产构建位于 dist。当前改动保存在工作区，未提交或发布。此记录对应架构书的基础修复与单图阶段，不代表自动整页/整章或复杂重绘已经完成。

## 基础修复

- 图片请求遇到 400 时不再删除图片重试；必需的结果格式也不由通用兼容逻辑删除。
- 普通 JSON 返回和 SSE 多种增量格式均可解析；截断、取消和重试等待有明确处理。
- 切换供应商时保存与恢复各自的自定义请求头；设置页的显示与编辑保持同步。
- 弹窗私有聊天与各网页文档的聊天隔离，图片读取校验所属会话。
- 聊天原图使用 IndexedDB，session 保存引用，历史只加载缩略图；旧 Base64 历史迁移。
- 会话与缓存按容量控制，辅助缓存写入失败不吞掉已完成的译文。
- 后台启动时清除过期 pending，并删除过期或失去会话引用的图片；清空聊天与关闭标签页清理相关任务。
- 漫画与实时字幕复用一个 offscreen 文档，分开管理任务；音频启动失败不会被覆盖成连接中。
- 版本元数据同步至当前 5.4.0；加入 Windows / Node 24 的测试构建工作流；测试并发限制为 2。

验证结果：

## 2026-09-09：真实 CPA 请求与模型路由修复

用户明确授权使用 `http://localhost:8317/management.html#/quota` 所属的本地 CPA Gemini 做实际测试。本次只读取该进程对应配置中的客户端 Key，在内存中请求同一服务的 `/v1/models` 和 `/v1/chat/completions`；没有改动 CPA、管理密钥、账号或路由配置，没有把 Key 放入脚本字面量、命令行、回复或结果日志。

根因及实测：

- 现有 `translateMangaTile` 原样发出 `gemini-3.8-flash` 时，约 99ms 返回 HTTP 400：`unknown provider for model gemini-3.8-flash`，错误码 `model_not_found`。先前默认模型 ID 没有在真实接口上核实，模拟测试掩盖了这个问题。
- 本机实际列表包含 `gemini-3.8-flash-high`，不包含 `gemini-3.8-flash`。只改模型 ID，保留图片、stream:true 和 json_schema，即在约 9.5 秒成功返回随机测试文字、译文与坐标；随机文字与图片完全一致。
- 使用最新扩展构建和全新的临时 Chromium 配置，设置页从真实 CPA 读取模型列表，识别旧 ID 不在列表中；通过下拉框选择完整 ID并确认保存。
- 点击实际“验证识图能力”，约 5.0 秒通过随机图片验证。随后打开少年ジャンプ＋同一公开章节，进入网站全屏，通过页内按钮选择两页；左页约 7.2 秒返回 12 个区域，右页约 6.6 秒返回 8 个区域，两页真实译文与坐标均显示在原图上。
- 这次模型回复没有模拟，没有额外回退到其他模型。临时浏览器在测试后清除了存储中的测试凭证并关闭，用户的常用浏览器配置没有被改动。

代码改动：

- 新漫画设置的模型 ID 留空，要求从真实服务商列表选择或手动填写；不再发明默认 ID，也不静默改写已经保存的模型。
- 新增漫画模型列表入口，使用所选服务商同一套地址、Key 和请求头读取 `/models`。只允许扩展设置页发起，响应有超时与大小上限，精确保留模型后缀；接口不支持列表时仍可手动输入。
- HTTP 400/404 中的明确模型路由错误映射为 `MODEL_NOT_FOUND`，显示请求中的模型名，不展示可能含凭证的原始上游错误；不为了模型不存在去剥离可选参数重试。
